# Supabase SQL migrations

## One-shot bundle (empty database only)

For a **new** Supabase project or an empty Postgres where nothing from this repo has been applied yet, you can paste the combined script:

- **`supabase/dist/all_migrations.sql`** — generated by [`scripts/combine-supabase-migrations.sh`](../scripts/combine-supabase-migrations.sh) from ordered files under [`migrations/`](./migrations/).

Regenerate after changing any migration:

```bash
./scripts/combine-supabase-migrations.sh
```

Do **not** run the full bundle on a database that already has tables/functions from these migrations; prefer the Supabase CLI migration workflow or apply **only** the new incremental files you are missing.

## Incremental migrations (existing database)

Apply files in chronological order from [`migrations/`](./migrations/) (e.g. via `supabase db push` or paste each new file once).

## Brisk-style UI vs pipeline stages

The Kanban UI shows **five** grouped columns (LEADS / DISCOVERY / DEMO / WON / LOST). Since `20260429140000_opportunities_pipeline.sql`, pipeline position is stored on **`opportunities.stage`** (one opportunity row per lead) using the granular **`lead_stage`** enum; **`leads.stage`** is now a mirror kept in sync by the `opportunities_sync_lead` trigger and is read by the scoring APIs. Write stage changes to `opportunities`, not `leads`.

The five column labels are a **frontend grouping/mapping** concern (`apps/web/lib/opportunities-kanban-columns.ts`), not separate database enums.

## New UI columns

`20260429130000_brisk_ui_fields.sql` adds optional **`companies.logo_url`**, **`companies.linkedin_url`**, **`company_segment`**, **`contacts.avatar_url`**, and **`marketing_channel_metrics`** for CAC-style snapshots (admin writes; authenticated read).

## Demo seed data

After migrations are applied, populate realistic CRM demo rows (users, companies, contacts, leads, activities, tasks, meetings, opportunities, proposals, marketing snapshots):

```bash
# From repo root — uses apps/api/.env (SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY).
# Prefer the API virtualenv so httpx is available:
apps/api/.venv/bin/python scripts/seed_database.py
```

- Connectivity is checked first (`GET /rest/v1/companies`).
- Creates three Auth users (`dracara.seed.admin@example.com`, `dracara.seed.agent@example.com`, `dracara.seed.sdr@example.com`) via the Admin API and sets roles **admin / agent / sdr**.
- Default password: **`DracaraSeed!2026`** (override with env **`SEED_PASSWORD`**).
- Re-running exits unless no seeded leads exist; use **`--force`** to insert again (may hit unique constraints on marketing metrics).
- **`--dry-run`**: connectivity + user creation only.

Log into the web app with any seed email and that password.
